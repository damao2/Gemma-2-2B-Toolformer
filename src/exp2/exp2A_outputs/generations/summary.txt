1. Quick sanity check: is the overall picture plausible?
Typical patterns per subset:

tool (in-distribution)
RAW: tool_call_rate=1.0, valid=1.0, math=1.0 at every layer (these 20 prompts are very clean).
FULL:
early and middle layers (4, 8, 12) barely hurt tool behaviour (still 1.0), with small CE fluctuations;
higher layers (16, 20, 24, 25) show a clear trade-off: higher CE and lower tool_call_rate (e.g. 0.7 at layer 20, 0.85 at layer 25).
NO_DELTA:
at most middle and high layers tool behaviour is wiped out (0 or very low at 16/20/12/...), and CE explodes (10-20+).
-> This matches expectations: the base SAE alone badly hurts tool behaviour; adding the delta brings it back at many layers, with some performance cost.

copy (negative prompts)
RAW: tool_call_rate=0.0 at every layer, as it should be.
FULL: essentially 0 at every layer, so the full SAE does not cause widespread spurious <tool_call> on copy prompts.
NO_DELTA:
0 at most layers;
anomalies only at some early layers:
layer 4: tool_call_rate=0.05 (1 of 20 prompts produced <tool_call>);
layer 0: tool_call_rate=1.0, valid=1.0, CE=17.78, a complete breakdown.
-> Apart from the extreme case of layer 0, behaviour is fine overall: no_delta hurts CE badly but does not systematically make the copy subset call the tool.

tool_ood (out-of-distribution)
RAW: consistently tool_call_rate=1.0, valid=0.4, math=0.35, i.e.
it always tries the tool, but format and arithmetic degrade on OOD prompts.
FULL:
CE fluctuates somewhat (worse at middle and high layers);
tool_call_rate stays close to 1.0 at most layers and drops only at 20/24/25 (e.g. 0.6 at layer 20).
NO_DELTA:
CE is mostly very high (16-26);
tool_call_rate drops clearly at high layers (e.g. layers 16/20/24/25: 0, 0.15, 0.65, 0.5);
but at layer 0 it is still tool_call_rate=1.0, valid=1.0, math=0.0.
-> no_delta shows an odd "always call the tool" tendency at early layers (especially layer 0), while at middle and high layers it often erases tool behaviour instead.

2. Why does no_delta give tool_call_rate=1.0 at layer 0, which looks implausible?
Key rows:

0,copy,no_delta,...,tool_call_rate=1.0,valid=1.0
0,tool,no_delta,...,tool_call_rate=1.0,valid=1.0,math=0.0
0,tool_ood,no_delta,...,tool_call_rate=1.0,valid=1.0,math=0.0
So at layer 0:

no_delta makes every subset "always output a well-formed-looking <tool_call>...",
but the arithmetic is almost always wrong (math_correct_rate=0),
and CE is extremely high (around 26).
This is not a bug in the metric logic. It looks more like this:

approximating the layer-0 MLP with the base SAE distorts the activations so badly that the rest of the network collapses: whatever the input, it heads towards an almost fixed tool-call snippet.

Behaviourally this is "implausible", but mathematically it is entirely possible:

layer 0 is very early, and intervening on it is very risky;
the SAE is Gemma-Scope's, trained on the base model, but here it is applied to the fine-tuned model;
the mismatch may be worst at layer 0;
the base SAE is not an exact equivalent transformation but an L1-sparse reconstruction, with projection error;
inserting a coarse approximation at an early layer easily squeezes the representations of all later tokens into a narrow region;
to the decoder, all prompts then "look alike", so it always takes some high-probability tool pattern.
CE confirms this: layer 0 no_delta has CE of 17-26 on every subset, a total breakdown rather than a "slight effect".

So:

tool_call_rate=1.0 is not a metric error; the model's behaviour has collapsed under this extreme intervention;
it is in fact an interesting negative result that can be used as evidence in the write-up:
"Approximating an early layer directly with the base SAE is very dangerous: it not only hurts the loss overall, but also makes the model systematically hallucinate tool calls on negative prompts."
3. Any sign that the metrics are implemented wrongly?
Cross-checking several layers, the metric implementation is self-consistent:

within a subset, raw is identical across layers while full/no_delta are not

e.g. the tool, raw row has the same values at every layer (1.0/1.0/1.0), which is correct because raw is the same model and does not depend on the layer.

tool, full and tool, no_delta vary strongly with the layer, so the hooks are really applied.

within a layer, the full vs no_delta difference goes in the expected direction

e.g. layer 20:

tool:
full: tool_call_rate=0.7, math=0.7
no_delta: tool_call_rate=0.15, math=0.15
copy:
tool_call_rate is 0 for both;
tool_ood:
full: tool_call_rate=0.6, math=0.0
no_delta: tool_call_rate=0.15, math=0.1
This matches the expectation that "delta rescues tool behaviour, base alone is poor".

mean_abs_base_acts / mean_abs_delta_acts vary plausibly with layer and subset

early layers (0-12) are around 20-50;
high layers (24-25) jump to 400-600;
delta is often larger on tool/tool_ood than on copy;
full and no_delta give very similar values, so the statistics are computed consistently.
Overall, there is no obvious sign of miscomputed metrics or swapped conditions. What is odd is the model's behaviour under some extreme interventions (especially layer 0 no_delta), not the code.

4. How to handle these anomalies in the analysis?
Suggestions:

mark layer 0 (and possibly layer 4) as "catastrophic" outlier layers and keep them out of the main conclusions:

grey them out or omit layer 0 in the plots;
explain in the text that the SAE approximation at early layers breaks every sub-task, including making the copy subset misuse the tool 100% of the time; this shows that such an approximation at early layers is very dangerous, but it is not a failure of delta fine-tuning itself.
focus on the patterns at middle and high layers (8, 12, 16, 20, 24, 25):

no_delta CE stays high;
on tool/tool_ood, tool_call_rate and math_correct_rate are clearly below raw;
full clearly restores tool behaviour at many layers, especially 8/12/16/24.
These form the main evidence for the two research questions.
To check that "layer 0 no_delta always emits <tool_call>" is real, inspect a few random lines of:

exp2A_outputs/generations/layer_0_copy_no_delta.jsonl
exp2A_outputs/generations/layer_0_tool_no_delta.jsonl
and confirm by eye that every prompt is turned into a similar <tool_call>... This can even serve as a qualitative example in an appendix, showing the catastrophic bias of the base SAE at early layers.

In one sentence
no_delta giving tool_call_rate=1.0 (especially at layer 0, on every subset) is behaviourally implausible but entirely possible under this intervention:
it shows that the base SAE approximation at layer 0 pushes the network into an almost fixed "always call the tool" attractor;
this is not a metric bug but a negative result to be reported separately as an "extreme early-layer SAE failure";
the main conclusions, including whether the delta is useful and more interpretable, should rest on the middle and high layers.
